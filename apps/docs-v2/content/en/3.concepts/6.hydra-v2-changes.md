Hydra V2 marks a significant evolution of the Hydra Head protocol. Starting from version 2.0.0, the protocol has been fundamentally simplified, making it easier to operate heads, reducing on-chain costs, and resolving long-standing issues.

## Overview

| Version | Release Date | Key Theme |
|---------|-------------|-----------|
| **2.0.0** | 2026-04-02 | Protocol simplification — remove commit phase, directly open heads |
| **2.1.0** | 2026-05-13 | Performance & security — SQLite event store, snapshots optimization, deposit hardening |

## 2.0.0 — Protocol Simplification

### Remove Commit Phase — Directly Open Heads

The most fundamental change in Hydra V2: **the commit phase is removed**. In V1, opening a head required all participants to commit UTxOs during an initialization phase (`Init` → `Commit` → `CollectCom`). In V2:

- Heads open **directly** after initialization — no `commit`, `collectCom`, or `abort` transactions.
- Funds are added **incrementally** via `deposit` transactions while the head is already open.
- This decision is documented in [ADR-33](https://hydra.family/head-protocol/adr/33).

**Benefits:**

- **Simplified lifecycle**: Removes the multi-step head opening process, reducing operational complexity.
- **Resolved "non-abortable head" issue**: Previously, a participant committing too large a UTxO could make the head un-abortable. This problem no longer exists.
- **Lower costs**: Eliminating `collectCom` and `abort` transactions reduces total on-chain costs for most use cases. See [transaction cost benchmarks](https://hydra.family/head-protocol/unstable/benchmarks/transaction-cost).

**API Changes:**

- `/commit` endpoint behavior changes — now accepts `deposit` transactions directly since heads open without a prior commit phase.
- Head initialization endpoint (`GET /head-initialization`) removed.
- All on-chain scripts changed — new script hashes across all networks.

### HydraHeadV2 Token

The head token name has been upgraded from `HydraHeadV1` to `HydraHeadV2`. This ensures version differentiation and prevents interaction between V1 and V2 heads.

### Conservative ADA Deposits

Until [partial fanout](https://github.com/cardano-scaling/hydra/pull/2324) is completed, the protocol encourages conservative ADA deposit amounts to maintain safety guarantees. The hard-coded 100 ADA commit limit on mainnet has been removed to match the behavior established in v1.3.0, but caution is advised for full fund safety.

### Bug Fixes

| Issue | Description |
|-------|-------------|
| **Plutus Script Evaluation** | L2 ledger `Globals` now uses era-aware `EpochInfo` queried from the blockchain instead of `fixedEpochInfo`, ensuring correct `POSIXTime` values for time-sensitive Plutus scripts on multi-era chains (mainnet/testnet). |
| **Stuck in RequestedSnapshot** | Fixed head getting permanently stuck when `CommitFinalized` races with an in-flight `ReqSn`. Only `SeenSnapshot` now blocks re-request; `RequestedSnapshot` retries correctly. |
| **Silently Dropped Deposits** | Active deposits that become active while a snapshot is in-flight are no longer silently dropped — the next chained snapshot picks them up via `selectNextDeposit`. |
| **Cross-Head Deposit Contamination** | Deposits from other heads are no longer picked up when multiple heads share the same network — `depositsForHead` is applied consistently. Deposit aggregate cases are guarded by `headId`. |

### Compatible Versions

- `cardano-node`: `10.6.2`
- `cardano-cli`: `10.15.0.0`
- `mithril`: `2524.0`

## 2.1.0 — Performance & Security

### SQLite-Backed Event Store

File-based persistence (append-only JSON `state` file) is replaced with a **SQLite-backed event store** (`hydra.db`):

- Events are persisted in `<persistence-dir>/hydra.db`
- On first startup after upgrading, existing `state` files are **automatically migrated** into `hydra.db` and renamed to `state.migrated`
- Improves node startup and recovery performance

### Deposit Security Hardening

The deposit Plutus validator has been hardened against **malformed increment transactions**, closing a security gap in on-chain deposit handling.

### Snapshot Latency Improvement

Snapshot confirmation latency reduced by **~7% (average)** by caching pre-computed signable bytes in `SeenSnapshot`. This avoids repeated UTxO serialization and hashing on every `AckSn` verification during signing rounds.

### Blockfrost Error Resilience

Transient chain-following errors in the Blockfrost backend (`DecodeError`, `MissingNextBlockHash`, etc.) are now retried with **exponential backoff** instead of crashing the node. HTTP-level API errors remain delegated to the upstream client library.

### Data Structure Optimization

- `List` replaced with `Seq` type to speed up transaction processing in certain operations.
- Several `StateChanged` event fields renamed or removed for clarity (see breaking changes below).

### Compatible Versions

- `cardano-node`: `11.0.1` (protocol version 12+)
- `cardano-cli`: `11.0.0`
- `mithril`: `2617`

## Breaking Changes Summary

### StateChanged Event Schema (2.1.0)

| Event | Change |
|-------|--------|
| `SnapshotRequested` | `snapshot` → `requestedSnapshot`; `requestedTxIds` removed (now carried inside snapshot) |
| `PartySignedSnapshot` | `snapshot :: Snapshot tx` → `snapshotNumber :: SnapshotNumber` |
| `SnapshotConfirmed` | `snapshot :: Snapshot tx` → `snapshot :: Maybe (Snapshot tx)` ( `Nothing` when snapshot already carried by `SnapshotRequested`) |
| `DecommitRecorded` | `utxoToDecommit :: UTxOType tx` field removed |

### Hydra Scripts

All on-chain scripts have new hashes across `preview`, `preprod`, and `mainnet` networks. Refer to the [networks.json](https://raw.githubusercontent.com/cardano-scaling/hydra/2.1.0/hydra-node/networks.json) for the latest script references.

### Persistence Migration

On upgrading from V1 to V2:
1. Close any open heads before upgrading.
2. The `state` file is automatically migrated to `hydra.db` on first 2.1.0 startup.
3. The original `state` file is renamed to `state.migrated` as backup.

## Migration Guide from V1 to V2

1. **Close all active heads** before upgrading the node.
2. **Update script references**: All hydra script hashes changed — update `--hydra-script-catalogue` or use `--network` flag.
3. **Update API consumers**: Adjust client code for the new `StateChanged` event schema (renamed/removed fields).
4. **Adapt deposit workflow**: Replace the commit-then-open pattern with direct-open-then-deposit.
5. **Verify persistence directory**: On first startup, existing `state` files will be auto-migrated to SQLite.
6. **Upgrade companion tools**: `cardano-node` `>= 11.0.1`, `cardano-cli` `>= 11.0.0`, `mithril` `>= 2617`.
