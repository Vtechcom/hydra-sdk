## July 2026 リリース — `transaction` v1.2.0 · `core` v1.4.1 · `bridge` v1.3.2 · `cardano-wasm` v1.0.0 (最新)

目玉は **`@hydra-sdk/transaction` v1.2.0** です — `TxBuilder` のメモリ安全性と機能のリリースです。`@hydra-sdk/cardano-wasm` も初の安定版 **v1.0.0** に到達しました。

### 🧠 メモリ安全性 — `@hydra-sdk/transaction`

- **WASM メモリリークと段階的な速度低下を修正**: すべての `@emurgo/cardano-serialization-lib` オブジェクトは WASM のリニアメモリに存在し、`.free()` によってのみ回収されます。CSL の `FinalizationRegistry` によるクリーンアップは非決定的で、タイトな構築ループには追いつけないため、WASM ヒープが際限なく増大し、トランザクションごとの構築時間が次第に劣化していました。`complete()` は現在、内部で割り当てたすべての CSL オブジェクトを `build_tx()` の後に決定的に解放します。測定結果: WASM メモリはフラット（~0 KB/iter）で、10,000 回の構築にわたってスループットが安定しました。既存の 280 テストは変更なしです。呼び出し側が提供したオブジェクト（datum / redeemer / script）は決して解放されません。
- **`completeCbor(): Promise<string>`**（新規）: トランザクションを構築してその CBOR hex を返し、中間の `Transaction` を即座に解放します — シリアライズされたバイトのみが必要な大量処理ワークロードのための、リークのない経路です。`complete()` は引き続きライブな `Transaction` を返します。呼び出し側がそれに対して `.free()` を呼び出す責任を負います。
- **`dispose()` + `[Symbol.dispose]`**（新規）: ビルダーが保持するすべての WASM メモリを解放します。`using` キーワード（`using tx = new TxBuilder()`）で動作します。GC に依存する代わりに、大量処理 / スパイクのワークロードに推奨されます。

### 🚀 新機能 — `@hydra-sdk/transaction`

- **stake 証明書が構築されるようになりました**: `registerStake()`、`deregisterStake()`、`delegateStake()` は以前、構築時に黙って破棄される証明書をステージングしていました — 現在は `set_certs` を通じて適用されるため、構築されたトランザクションに実際に証明書が含まれます。stake credential は bech32 の reward（stake）アドレスから解決されます。無効な reward アドレスは、無視されるのではなくエラーをスローするようになりました。`PoolRegistration` / `PoolRetirement` は明確な「まだサポートされていません」エラーをスローします。
- **`totalCollateral()` が適用されるようになりました**: `set_total_collateral` を通じて構築されたトランザクションに適用されます（以前は値が保存されるだけで、書き込まれることはありませんでした）。
- **オプションのスクリプト exUnits 評価**: `TxBuilder` は `evaluator?: IEvaluator`（および安全マージンの `txEvaluationMultiplier?`）を受け取ります。指定され、かつトランザクションに Plutus redeemer が含まれる場合、`complete()` は 2 回目の構築パスを実行します — ドラフトのトランザクションを評価して実際の `exUnits` を取得し、それらを redeemer に書き戻し（`SPEND` は入力の `txHash#index` で照合、`MINT` は policy id で照合）、fee が正確になるようにトランザクションを再構築します。evaluator がない場合（例: オンチェーンのスクリプト評価を持たない Hydra の場合）、動作は変わりません。`IEvaluator` / `EvalAction` / `Budget` の型は、相互運用性のために MeshJS を反映しています。_現在の制限:_ `SPEND` と `MINT` の budget のみが再マッピングされ、オフライン evaluator はまだバンドルされていません — プロバイダーに裏付けられたもの（Blockfrost / Ogmios / Demeter）または UPLC evaluator を提供してください。

### 🐛 バグ修正 — `@hydra-sdk/transaction`

- **スクリプトトランザクションの fee 修正**: ビルダーの設定は以前、`ex_unit_prices` をゼロに、`ref_script_coins_per_byte` を `15/1` にハードコードしていたため、スクリプト実行の fee コンポーネント（`priceMem·exMem + priceStep·exSteps`）が省略され、reference script の価格設定がプロトコルパラメータを無視していました — スクリプトトランザクションへの資金が不足していました。現在は両方ともプロトコルパラメータ（`priceMem`、`priceStep`、`minFeeRefScriptCostPerByte`）から取得されます。スクリプトを使わない送金はすでに正しく動作していました。
- **`reset()` の use-after-free を修正**（メタデータコンテナが解放されたのに再作成されていませんでした）。また、コンストラクタは `params` が指定された場合に、基盤となる `TransactionBuilder` を二重に割り当てなくなりました。

### 📦 `@hydra-sdk/cardano-wasm` v1.0.0 — 初の安定版リリース

- WASM ラッパーが **v1.0.0** に到達しました。package.json の `exports` conditions（`browser` → browser WASM、`node` → Node.js）を通じて正しい `@emurgo/cardano-serialization-lib` ビルドを選択し、asm.js フォールバックは `@hydra-sdk/cardano-wasm/asmjs` サブパスでオプトインできます。安定版になったので、他の依存関係と同様に固定してください（`^1.0.0`）。

## バージョン 1.4.0 - July 2026

### 🚀 新機能 — `@hydra-sdk/core`

- **`RedeemerUtils` — 新しい名前空間**: `RedeemerUtils.mkRedeemer(data, options?)` は任意の `PlutusData`（例: `DatumUtils` で構築したもの）を、設定可能な `tag` / `index` / `exUnits` を持つ `Redeemer` にラップし、`@hydra-sdk/transaction` の `TxBuilder` にそのままアタッチできるようにします。便利なヘルパー `mkSpendRedeemer`、`mkMintRedeemer`、`mkUnitRedeemer` に加え、低レベルの `mkRedeemerTag`、`mkExUnits`、`DEFAULT_EX_UNITS` も含まれています。

  ```typescript
  import { RedeemerUtils, DatumUtils } from '@hydra-sdk/core'

  const data = DatumUtils.mkConstr(1, []) // e.g. a `Cancel` redeemer
  const redeemer = RedeemerUtils.mkRedeemer(data, { tag: 'spend', index: 0 })
  ```

- **`DatumUtils` — 新しい Plutus データエンコーダー**:
  - `mkBool` — Aiken の `Bool` をエンコードします（`False = Constr(0, [])`、`True = Constr(1, [])`）。
  - `mkOption` — `Option`/`Maybe` をエンコードします（`Some = Constr(0, [v])`、`None = Constr(1, [])`）。
  - `mkBytesList` / `mkIntList` — `List<ByteArray>` / `List<Int>` をエンコードします。
  - `mkOutputRef` — Plutus の `OutputReference` をエンコードします（`Constr(0, [Bytes(txHash), Int(index)])`）。
  - `mkAddress` / `parseAddress` — bech32 アドレスと Plutus の `Address` データを相互に変換します。

- **`Deserializer.deserializeAmountsFromTx(cborHex)`**: トランザクションの CBOR をデコードし、**すべて**の出力にわたるあらゆる量（lovelace + ネイティブトークン）を返します。`unit` ごとにマージされ、数量が合計されます。`Asset[]` を返します。

  ```typescript
  const amounts = Deserializer.deserializeAmountsFromTx(txCborHex)
  // [{ unit: 'lovelace', quantity: '2000000' }, { unit: '<policy><assetName>', quantity: '5' }]
  ```

### ♻️ リファクタリング — `@hydra-sdk/core`

- **アドレス検証を `validator.util` から移動**: `AddressUtils.isValidAddress` と新しい `ValidationUtils.isValidTxOutput` がこれらのヘルパーを保持するようになりました（以前は `validator.util` にありましたが、この名前は Plutus の **validator スクリプト** と混同されやすいものでした）。`ValidatorUtils` は後方互換性のために **非推奨** の再エクスポートとして残されています。既存の `ValidatorUtils.isValidAddress` / `ValidatorUtils.isValidTxOutput` の呼び出しは引き続き動作しますが、新しいコードでは `AddressUtils.isValidAddress` / `ValidationUtils.isValidTxOutput` を使用してください。

### 🔧 プロトコル — `@hydra-sdk/core`

- **プロトコルパラメータを v11 にアップグレード**: `DEFAULT_PROTOCOL_PARAMETERS.minPoolCost` が `340000000`（340 ADA）から `170000000`（170 ADA）に引き下げられ、Cardano v11 のプロトコルパラメータ更新に対応しました。
- **コストモデルを v11 のオンチェーンコストモデルと同期**: `DEFAULT_V1_COST_MODEL_LIST` / `DEFAULT_V2_COST_MODEL_LIST` に追加の Plutus 組み込みコストエントリを拡張し、`DEFAULT_V3_COST_MODEL_LIST` の係数を v11 の値に更新しました。

### 🐛 バグ修正 — `@hydra-sdk/core`

- **`Resolver.resolveTxHash` の WASM メモリリーク**: 返す前に中間の `FixedTransaction` WASM オブジェクトに対して `.free()` を呼び出すようになり、多数のトランザクションをハッシュ化する長時間実行プロセスでの WASM ヒープの増大を防ぎます。

### 📦 更新されたパッケージ

- `@hydra-sdk/core@1.4.0`

## バージョン 1.3.2 - June 2026

### 🚀 新機能 — `@hydra-sdk/core`

- **`DemeterProvider` — 新しいプロバイダー**: [Demeter](https://demeter.run) のホスト型エンドポイント向けの Blockfrost 互換プロバイダーです。`BlockfrostProvider` を拡張し、`authToken` と `network` フィールドから認証済みエンドポイント URL を自動的に構築します。

  ```typescript
  import { ProviderUtils } from '@hydra-sdk/core'

  const provider = new ProviderUtils.DemeterProvider({
    authToken: 'blockfrost102lx3ckhzvkjjh7677g',
    network: 'mainnet', // 'mainnet' | 'preprod' | 'preview'
  })
  ```

- **`BlockfrostProviderConfig.baseURL`**: デフォルトの Blockfrost エンドポイント URL を呼び出し側が上書きできる、新しいオプションフィールドです（`DemeterProvider` によって内部的にも使用されます）。
- **`DatumUtils.mkList(elements)`**: `PlutusData` 要素の配列から `PlutusData` のリストを構築し、`mkInt`、`mkBytes`、`mkConstr`、`mkMap` とともに datum ビルダー API を完成させます。

### 🐛 バグ修正 — `@hydra-sdk/core`

- **`metadataObjToMetadatum` の検証とロジックの修正**: 文字列とバイトに対する UTF-8 バイト長の検証を Cardano の 64 バイト制限に照らして行い（説明的なエラー付き）、float 値に対する `Number.isInteger()` ガード、および専用の `Map` 分岐を追加しました（以前は空の `Map` が黙ってデータを失っていました）。

## バージョン 1.3.1 - March 18, 2026

### 🐛 バグ修正 — `@hydra-sdk/bridge`

- **Greetings の `Idle` head ステータスでのクラッシュ**: `headStatus` が `Idle`（head がまだ開かれていない）場合、`Greetings` メッセージには `snapshotUtxo` フィールドが含まれません。これにアクセスすると `undefined` エラーが発生し、キャッシュのシード処理が壊れていました。ハンドラは `updateSnapshot` を呼び出す前に、欠落しているフィールドをガードするようになりました。

### 🛠️ 開発者体験 — `@hydra-sdk/bridge`

- **Chalk による色付けされた詳細ログ**: `HydraBridge` 全体のすべての `console.log/warn/error` 呼び出しが、`chalk` に基づく 3 つのモジュールレベルのヘルパー（`log`、`warn`、`err`）に置き換えられました:
  - タグ `[⚡ HydraBridge]` は常に **シアンの太字** で出力されます
  - 成功イベント（接続完了、snapshot のシード完了）は **緑** を使用します
  - 警告（再接続の試行、順序が乱れた snapshot）は **黄** を使用します
  - エラーと切断イベントは **赤** を使用します
  - 重要度の低い値（txId、slot のタイムスタンプ）は **グレー** を使用します
- **デバッグダンプの削除**: 残っていた 2 つの `console.log('>>> / bridge.ts:...')` 文が削除されました。

### 📦 更新されたパッケージ

- `@hydra-sdk/bridge@1.3.1`

## バージョン 1.3.0 - March 16, 2026

### 🚀 新機能 — `@hydra-sdk/bridge`

- **hydra-node v1.3.0 との互換性**: `Greetings` メッセージに 4 つの新しいオプションフィールド `currentSlot`、`chainSyncedStatus`、`env`、`networkInfo` が追加されました
- **スロットゼロのタイムスタンプ**: `HydraBridge.slotZeroTimestamp` — Hydra Head 内での slot ↔ 時刻の計算のために、`Greetings.currentSlot` から自動的に導出されます
- **`submitTx` コールバック API**: 既存の `submitTxSync` に加わる、新しい Node.js のエラーファーストなコールバックメソッドです:
  ```typescript
  bridge.submitTx(tx, (error, result) => { ... }, { timeout: 30000 })
  ```
- **`/head` API の修正**: `HydraHeadInfo` 型が、実際の hydra-node v1.3.0 の `/head` レスポンス構造に合わせて書き直されました
- **自動再接続**: 3 つの新しい `InitHydraBridgeOptions` フィールド — `autoReconnect`、`reconnectInterval`（デフォルト 3000ms）、`maxReconnectAttempts`（0 = 無制限）

### ⚡ パフォーマンス — `@hydra-sdk/bridge`

- **O(1) の残高ルックアップ**: 事前計算された `balanceCache: Map<address, Map<assetUnit, bigint>>` — snapshot ごとに一度だけ再構築され、リクエストごとに I/O なしで読み取られます
- **O(1) の UTxO ルックアップ**: 事前構築された `addressUtxoIndex: Map<address, UTxOObject>` — `queryAddressUTxO()` と `addressesInHead()` は呼び出しごとにすべての UTxO をスキャンしなくなりました
- **`getAddressBalance(address)`**: 残高を即座に読み取るための新しいパブリック API です。コールドスタート時（キャッシュがまだシードされていない）には `null` を返します
- **`lastSnapshotNumber`**: パブリックフィールドとして公開されます。キャッシュは前進するのみで、再接続や順序の乱れた配信でも後退することはありません
- **Greetings によるキャッシュのシード**: 新規接続時に HTTP のラウンドトリップは不要です — `Greetings` メッセージの `snapshotUtxo` がインデックスを直接シードします
- **HTTP フォールバックの競合状態の修正**: 遅い HTTP レスポンスが、より新しい WebSocket の snapshot データを上書きすることがなくなりました

### ⚡ パフォーマンス — `@hydra-sdk/core`

- **`convertUTxOObjectToUTxOWithOptions`**: `{ maxDatumCacheSize?: number }` を受け取る新しいエクスポートです — datum のデシリアライズキャッシュが LRU による退避で上限付き（デフォルト 1024）になり、大きな snapshot でのメモリの際限のない増大を防ぎます
- **Converter のリファクタリング**: `convertUTxOToUTxOObject` と `convertTxOutputToWasm` で `reduce` → `for` ループに変更、`convertUTxOObjectToUTxO` では中間配列の割り当てを避けるために `Object.entries()` を `for...in` に置き換えました
- **ベンチマークスクリプト**: `scripts/bench-converter.ts` — 設定可能なワークロードのもとで変換スループットを測定する CLI ツールです

### 🐛 バグ修正 — `@hydra-sdk/bridge`

- **`submitTxSync` の変数シャドーイング**: 内側の `tx` が外側の `tx` パラメータをシャドーイングしていました — 一致するトランザクションではなく、常に最初に確認されたトランザクションを返していました
- **`newTx` のハードコードされた description**: 呼び出し側が指定した description を `'Ledger Cddl Format'` で上書きしていました。現在はそのまま渡されます
- **URL ビルダーのデフォルトポート**: `buildUrl` は明示的なポートが指定されない場合に `https://host:443/path` を出力していました。現在はデフォルトポートが取り除かれます

### 🛠️ 内部リファクタリング

- **`awaitHydraMessage` ユーティリティ** (`src/utils/await-hydra-message.ts`): 繰り返されていた手動のイベントリスナー + タイムアウトのクリーンアップパターンを置き換えます。`submitTxSync`、`decommit`、`initHydraHead` はすべてこれを使うようにリファクタリングされ、壊れやすい複数の終了経路でのクリーンアップがなくなりました

### 📦 更新されたパッケージ

## 🔄 移行に関する注意

### パッケージ命名規則

バージョン 1.0.5 以降、より良い一貫性のために、すべてのパッケージが `@hydrawallet-sdk/*` から `@hydra-sdk/*` の命名規則に移行されました。

### 推奨設定 (v1.0.13+)

最適なパフォーマンスのために、Vite の設定を更新することをお勧めします:

**推奨されるセットアップ:**

```javascript
nodePolyfills({
	include: ['buffer'], // ✅ Only include buffer polyfill
	globals: {
		Buffer: true, // ✅ Required for cryptographic operations
		global: false, // ✅ Disabled for better performance
		process: false // ✅ Disabled for better performance
	}
})
```

**レガシーなセットアップ（引き続きサポート）:**

```javascript
nodePolyfills({
	globals: {
		Buffer: true,
		global: true, // ⚠️ Not recommended but still works
		process: true // ⚠️ Not recommended but still works
	}
})
```

### 破壊的変更

- **v1.1.0**: 主要な TimeUtils API の変更 - `resolveSlotNo()` は非推奨、`SLOT_CONFIG_NETWORK` とともに `unixTimeToEnclosingSlot()` を使用してください
- **v1.1.0**: DatumSchema API を簡素化 - `fromJSON()`/`toJSON()` メソッドを削除、定数のみを使用してください
