Hydra SDK は `hydra-node` と通信し、ノードは Hydra Head プロトコル独自のリリースサイクルに従います。このページではそのサイクルと、SDK がサポートするノードバージョンを追跡します。

::note
`@hydra-sdk/bridge` **2.x は hydra-node v2 系列を対象とします**（**2.3.0** で検証済み）。bridge のメジャーバージョンは hydra-node のメジャーバージョンに追従します。

bridge **1.x はサポート終了**です。v1 の **commit ベース** のフローに対応していましたが、今後のリリースはありません。v2 では commit フェーズが完全に廃止され（ADR-33）、Head は直接オープンし、資金は **incremental deposit** で入ります。アップグレードは破壊的変更です。[マイグレーションガイド](/resources/migration)を参照してください。
::

## v1.3.0 — 安定版 v1 系列

`1.3.0` は v1 系列で最大かつ最も安定したリリースであり、`@hydra-sdk/bridge` によって完全にサポートされています。SDK 統合に関連する主なポイント:

- **手数料が約 4 倍安く** — 手数料見積もりの改善により、`init` / `open` および関連するオンチェーントランザクションが安くなりました。
- **同期外れ保護（破壊的変更）** — ノードはチェーンより遅れている間、入力を拒否するようになり、`NodeUnsynced` / `NodeSynced` の状態を明らかにします。クライアントコードは送信前に `NodeSynced` を待つべきです。
- **リッチになった `Greetings`（破壊的変更）** — greeting メッセージが `currentSlot` と同期ステータスを含むようになりました。`@hydra-sdk/bridge` はこれらの拡張フィールドを読み取ります。
- **より長い contestation 期間（破壊的変更）** — `defaultContestationPeriod` が 10 分から **12 時間** に変更され、Head を閉じるのにかかる時間に影響します。
- **snapshot ごとのトランザクション数の上限** と、チェーンのロールバックをまたぐ deposit/decommit の修正。

**互換ツール:** `cardano-node 10.6.2` · `cardano-cli 10.15.0.0` · `mithril 2524.0`

::note
`v1.2.1`（pre-release）は、V2 の era-aware `EpochInfo` 修正を v1 系列にバックポートし、マルチエラのチェーン上で Plutus `ScriptContext` 内の `POSIXTime` 値を修正します。これは pre-release です。`1.3.0` を推奨します。
::

以下はすべて **V2 系列** について説明します。これは Head のライフサイクルとオンチェーンスクリプトを変更します。V2 は `2.2.0` で安定しました。

## 2.0.0 — プロトコルの簡素化

### commit フェーズの削除 — Head を直接開く

Hydra V2 における最も根本的な変更は、**commit フェーズが削除された** ことです。V1 では、Head を開くには初期化フェーズ（`Init` → `Commit` → `CollectCom`）中にすべての参加者が UTxO を commit する必要がありました。V2 では:

- Head は初期化後に **直接** 開きます。`commit`、`collectCom`、`abort` トランザクションはありません。
- 資金は Head が既に開いている間に `deposit` トランザクションを介して **incremental に** 追加されます。
- この決定は [ADR-33](https://hydra.family/head-protocol/adr/33) に記録されています。

**利点:**

- **ライフサイクルの簡素化**: 複数ステップの Head 開設プロセスを削除し、運用の複雑さを軽減します。
- **「abort できない Head」問題の解決**: 以前は、大きすぎる UTxO を commit した参加者が Head を abort できなくするおそれがありました。この問題はもう存在しません。
- **コストの低減**: `collectCom` と `abort` トランザクションを排除することで、ほとんどのユースケースで総オンチェーンコストが削減されます。[トランザクションコストのベンチマーク](https://hydra.family/head-protocol/unstable/benchmarks/transaction-cost) を参照してください。

**API の変更:**

- `/commit` エンドポイントの挙動が変わります。Head は事前の commit フェーズなしで開くため、`deposit` トランザクションを直接受け付けるようになりました。
- Head 初期化エンドポイント（`GET /head-initialization`）が削除されました。
- すべてのオンチェーンスクリプトが変更されました。全ネットワークで新しいスクリプトハッシュになります。

### HydraHeadV2 トークン

Head トークン名が `HydraHeadV1` から `HydraHeadV2` にアップグレードされました。これによりバージョンの区別が確実になり、V1 と V2 の Head の相互作用が防止されます。L1 上でトークン名により Head を識別するコードは更新する必要があります。

### Era-aware な Plutus スクリプト

L2 台帳の `Globals` は、`fixedEpochInfo` の代わりにブロックチェーンからクエリした era-aware `EpochInfo` を使用するようになり、マルチエラのチェーン（mainnet/testnet）で時間に依存する Plutus スクリプトに対して正しい `POSIXTime` 値を保証します。

### Snapshot と deposit の修正

| 問題 | 説明 |
|-------|------|
| **RequestedSnapshot でスタック** | `CommitFinalized` が処理中の `ReqSn` と競合すると Head が永久にスタックする問題を修正しました。現在は `SeenSnapshot` のみが再リクエストをブロックします。`RequestedSnapshot` は正しくリトライします。 |
| **静かに破棄される deposit** | snapshot の処理中にアクティブになる deposit は、もはや静かに破棄されません。次にチェーンされる snapshot が `selectNextDeposit` を介してそれらを取り込みます。 |
| **Head をまたぐ deposit の混入** | 複数の Head が同じネットワークを共有する場合に、他の Head からの deposit がもはや取り込まれません。`depositsForHead` が一貫して適用され、deposit の集約ケースは `headId` で保護されます。 |
| **100 ADA の commit 上限を削除** | ハードコードされた 100 ADA の mainnet commit 上限が削除されました。`2.2.0` までは、完全な資金の安全のために保守的な deposit 額が依然として推奨されていました。`2.2.0` の **部分 fanout** 機能（後述）がその上限を完全に取り払います。 |

## 2.1.0 — 永続化と回復力

::note
`2.1.0` は `2.2.0` によって置き換えられています。V2 系列では `2.2.0` を推奨します。
::

### SQLite バックエンドのイベントストア

ファイルベースの永続化（追記専用の JSON `state` ファイル）は **SQLite バックエンドのイベントストア**（`hydra.db`）に置き換えられました:

- イベントは `<persistence-dir>/hydra.db` に永続化されます。
- アップグレード後の初回起動時に、既存の `state` ファイルは `hydra.db` に **自動的に移行** され、`state.migrated` にリネームされます。
- 起動とリカバリのパフォーマンスが大幅に向上します。

### Deposit のセキュリティ強化

deposit の Plutus validator が **不正な形式の increment トランザクション** に対して強化され、オンチェーンの deposit 処理におけるセキュリティのギャップが解消されました。

### Snapshot レイテンシの改善

事前計算された署名可能バイトを `SeenSnapshot` にキャッシュすることで、snapshot 確定のレイテンシが **平均で約 7%** 削減されます。これにより、署名ラウンド中の `AckSn` 検証のたびに繰り返される UTxO のシリアライズとハッシュ化が回避されます。

### Blockfrost エラーへの回復力

Blockfrost バックエンドにおける一時的なチェーン追従エラー（`DecodeError`、`MissingNextBlockHash` など）は、ノードをクラッシュさせる代わりに **指数バックオフ** でリトライされるようになりました。

### その他の変更

- 特定の操作でトランザクション処理を高速化するため、`List` が `Seq` に置き換えられました。
- いくつかの `StateChanged` イベントフィールドがリネームまたは削除されました（後述の破壊的変更を参照）。
- `cardano-node` プロトコルバージョン 12+ にアップグレードされました。

**互換ツール:** `cardano-node 11.0.1` · `cardano-cli 11.0.0` · `mithril 2617`

## 2.2.0 — 部分 fanout とより安価な L2

これは現行の安定版 V2 リリースです。

### 部分 fanout — Head ごとの UTxO 上限がなくなる

これまで、Head が保持できる UTxO の数は、実質的に単一の fanout トランザクションに収まる量によって上限が決まっていました。**部分 fanout** はその制限を取り除きます:

- 任意に大きな UTxO 集合を持つ Head は、複数のステップにわたってクローズアウトされます。各 `PartialFanoutTx` は 1 つのトランザクションに収まるだけの出力を分配し、最後の `FinalPartialFanoutTx` が Head トークンを burn してプロセスを完了します。
- すべてのステップは **BLS accumulator メンバーシップ証明** によりオンチェーンで検証されます。
- チャンクサイズはハードコードされた制限ではなく、**動的に**（有効なサイズに対する二分探索で）決定されます。

これにより V2 の初期リリースにあった保守的な deposit の注意点が解消されます。

### より安価な L2 トランザクション

`utxoCostPerByte` は L2 上で **ゼロ** に設定されるため、`NewTx` はわずか **1 lovelace** で送信でき、Head 内でのトランザクションのコストを下げます。

### 刷新された hydra-tui

`hydra-tui` が大幅に改訂されました。`Open` および `Closed`/`Final` 状態からの保留中 deposit のリカバリ、config に永続化されるダーク/ライトのテーマ切り替え、イベント履歴のフィルタ（全体 vs エラーのみ）、タブナビゲーションが含まれます。

### 正確性とパフォーマンスの修正

- 以前の Head から永続化されたイベントを再生すると、新しく開いた Head の状態が破損する問題を修正しました。
- snapshot をサイドロードした後に、リカバリされた incremental-commit の deposit が L2 UTxO に再出現する問題（同じ UTxO が L1 と L2 で同時に使用可能になっていた）を修正しました。
- `Increment` と `Decrement` の validator 遷移に `mustNotMintOrBurn` ガードを追加しました。
- 冗長な `newLocalUTxO` フィールドを削除することで、ディスク上のイベントストアの肥大化を軽減しました（トランザクション後の UTxO は算術的に再計算されます）。
- 遅延 `Map` が **strict `Map`** に置き換えられ、メモリ使用量が改善されました。

**互換ツール:** `cardano-node 11.0.1` · `cardano-cli 11.0.0` · `mithril 2617`

## 破壊的変更のまとめ (V2)

### 2.1.0 — StateChanged イベントスキーマ

| イベント | 変更 |
|-------|------|
| `SnapshotRequested` | `snapshot` → `requestedSnapshot`; `requestedTxIds` を削除（現在は snapshot の内部で保持） |
| `PartySignedSnapshot` | `snapshot :: Snapshot tx` → `snapshotNumber :: SnapshotNumber` |
| `SnapshotConfirmed` | `snapshot :: Snapshot tx` → `snapshot :: Maybe (Snapshot tx)`（snapshot が既に `SnapshotRequested` によって保持されていた場合は `Nothing`） |
| `DecommitRecorded` | `utxoToDecommit :: UTxOType tx` フィールドを削除 |

### 2.2.0 — Fanout と UTxO フィールド

| フィールド / イベント | 変更 |
|---------------|------|
| `HeadIsFinalized` (server output) | `utxo` → `finalizedUTxO`; 型が UTxO マップ（`TxIn` をキーとする）から **`TxOut` の配列** に変更（中間の部分 fanout 出力は使用参照を持ちません） |
| `ClosedState` (persisted) | `remainingFanoutUTxO` → `remainingFanoutOutputs`, `distributedFanoutUTxO` → `distributedFanoutOutputs`; 両方とも UTxO マップ → **`TxOut` の配列** |
| `TransactionAppliedToLocalUTxO`, `SnapshotRequested`, `DecommitRecorded` | `newLocalUTxO` フィールドを削除 |

### Hydra スクリプトハッシュ

オンチェーンスクリプトはプロトコル変更のたびに新しいハッシュを持ちます。**v1.3.0** と **V2** 系列（どちらも bridge によりサポート）について:

| ネットワーク | 1.3.0 | 2.1.0 | 2.2.0 (two scripts) |
|---------|-------|-------|---------------------|
| `preview` | `8ae405c2…cf88621` | `86288ee0…add66c4` | `52c84ab1…e799ad6c`, `dd4b3920…afb95f41` |
| `preprod` | `476b37a7…a11e8f3da` | `16f275a5…54298e46` | `2c01bf78…9ea00b03`, `395ecc51…af4696dd` |
| `mainnet` | `2c6cff50…4d5e8b67` | `a864514b…c45539da2` | `17fb77e1…b29d276b9`, `906ecc6e…76dbfc4a3` |

`2.2.0` は部分 fanout が accumulator スクリプトを追加するため、ネットワークごとに **2 つの** スクリプトハッシュを公開します。正確なノードバージョンについては、常に完全なハッシュを [networks.json](https://github.com/cardano-scaling/hydra/blob/master/hydra-node/networks.json) と照合してください。

## ノードを V1 から V2 へ移行する

V1 → V2 はプロトコルレベルでの **破壊的で一方向の変更** です。プロトコル、トークン、スクリプトが異なり、V1 ノードと V2 ノードの間に後方互換性はありません。`@hydra-sdk/bridge` は両方の系列をサポートするため、SDK の変更は不要です。ノードを V1 から V2 に切り替える際は:

1. ノードをアップグレードする前に **すべてのアクティブな Head を閉じます**。
2. **スクリプト参照を更新します** — すべての hydra スクリプトハッシュが変更されました。ネットワーク/スクリプトの設定を更新してください。
3. **API コンシューマーを更新します** — 新しい `StateChanged` イベントスキーマ、`HeadIsFinalized`/`ClosedState` のフィールド変更、削除された head-initialization エンドポイントに合わせてクライアントコードを調整してください。
4. **deposit ワークフローを適応させます** — commit してから open するパターンを、直接 open してから deposit するパターンに置き換えてください。
5. **永続化ディレクトリを確認します** — 既存の `state` ファイルは初回起動時に SQLite へ自動移行されます。
6. **付随ツールをアップグレードします** — `cardano-node >= 11.0.1`, `cardano-cli >= 11.0.0`, `mithril >= 2617`。
