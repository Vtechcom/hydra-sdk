# Hydra V2 の変更点

Hydra V2 は Hydra Head プロトコルの重要な進化を示します。バージョン 2.0.0 から、プロトコルは根本的に簡素化され、Head の運用が容易になり、オンチェーンコストが削減され、長年の課題が解決されました。

## 概要

| バージョン | リリース日 | 主なテーマ |
|-----------|----------|-----------|
| **2.0.0** | 2026-04-02 | プロトコル簡素化 — commit フェーズの削除、Head を直接オープン |
| **2.1.0** | 2026-05-13 | パフォーマンス & セキュリティ — SQLite イベントストア、スナップショット最適化、deposit の保護 |

## 2.0.0 — プロトコル簡素化

### Commit フェーズの削除 — Head を直接オープン

Hydra V2 で最も根本的な変更: **commit フェーズが削除されました**。V1 では、Head を開くには全参加者が初期化フェーズ (`Init` → `Commit` → `CollectCom`) で UTxO を commit する必要がありました。V2 では:

- Head は初期化後**直接**オープン — `commit`、`collectCom`、`abort` トランザクションは不要。
- 資金は Head が既にオープンしている状態で `deposit` トランザクションを介して**段階的に**追加。
- この決定は [ADR-33](https://hydra.family/head-protocol/adr/33) に文書化されています。

**利点:**

- **簡素化されたライフサイクル**: 複数ステップの Head オープニングプロセスを排除し、運用の複雑さを軽減。
- **"non-abortable head" 問題の解決**: 以前は、参加者が大きすぎる UTxO を commit すると Head が abort できなくなることがありました。この問題は解消されました。
- **低コスト**: `collectCom` と `abort` トランザクションの排除により、ほとんどのユースケースで総オンチェーンコストが削減。[transaction cost benchmarks](https://hydra.family/head-protocol/unstable/benchmarks/transaction-cost) を参照。

**API 変更:**

- `/commit` エンドポイントの動作が変更 — 事前の commit フェーズなしで Head がオープンするため、`deposit` トランザクションを直接受け付け。
- Head 初期化エンドポイント (`GET /head-initialization`) が削除。
- すべてのオンチェーンスクリプトが変更 — 全ネットワークで新しいスクリプトハッシュ。

### HydraHeadV2 トークン

Head トークン名が `HydraHeadV1` から `HydraHeadV2` にアップグレードされました。これによりバージョンの区別が確保され、V1 と V2 の Head 間の相互作用が防止されます。

### 保守的な ADA Deposit

[partial fanout](https://github.com/cardano-scaling/hydra/pull/2324) が完了するまで、プロトコルは安全性を維持するために保守的な ADA deposit 額を推奨します。メインネットでの 100 ADA のハードコードされた commit 制限は削除され、v1.3.0 の動作と一致しますが、完全な資金の安全性のためには注意が必要です。

### バグ修正

| 問題 | 説明 |
|------|------|
| **Plutus Script Evaluation** | L2 ledger の `Globals` が `fixedEpochInfo` の代わりにブロックチェーンから取得した era-aware な `EpochInfo` を使用し、複数 era のチェーン (mainnet/testnet) で時間依存の Plutus スクリプトに対して正しい `POSIXTime` 値を確保。 |
| **RequestedSnapshot でスタック** | `CommitFinalized` が処理中の `ReqSn` と競合した際に Head が永続的にスタックする問題を修正。`SeenSnapshot` のみが再リクエストをブロックし、`RequestedSnapshot` は正しくリトライ。 |
| **Deposit の消失** | スナップショット処理中にアクティブになった deposit が消失する問題を修正 — 次のチェーンされたスナップショットが `selectNextDeposit` で取得。 |
| **クロス Head Deposit 混入** | 複数の Head が同じネットワークを共有する場合に、他の Head の deposit が誤って取得される問題を修正 — `depositsForHead` が一貫して適用され、deposit aggregate が `headId` で保護。 |

- `cardano-cli`: `10.15.0.0`
- `mithril`: `2524.0`

## 2.1.0 — パフォーマンス & セキュリティ

### SQLite イベントストア

ファイルベースの永続化 (追記専用 JSON `state` ファイル) が **SQLite イベントストア** (`hydra.db`) に置き換え:

- イベントは `<persistence-dir>/hydra.db` に保存
- アップグレード後の初回起動時に、既存の `state` ファイルは **自動的に移行** され `hydra.db` に変換、`state.migrated` にリネーム
- ノードの起動とリカバリのパフォーマンスが向上

### Deposit のセキュリティ強化

Deposit Plutus validator が **不正な increment トランザクション** に対して強化され、オンチェーン deposit 処理のセキュリティギャップが解消されました。

### スナップショット遅延の改善

スナップショット確認遅延が **約 7% (平均)** 削減。事前計算された署名可能バイトを `SeenSnapshot` にキャッシュすることで、署名ラウンド中の各 `AckSn` 検証での UTxO シリアライズとハッシュの繰り返しを回避。

### Blockfrost エラー耐性

Blockfrost バックエンドでの一時的なチェーン追随エラー (`DecodeError`、`MissingNextBlockHash` など) が、ノードをクラッシュさせる代わりに **指数バックオフ** でリトライされるようになりました。HTTP レベルの API エラーは引き続きアップストリームクライアントライブラリに委譲されます。

### データ構造の最適化

- 特定の操作でトランザクション処理を高速化するため、`List` を `Seq` に置き換え。
- いくつかの `StateChanged` イベントフィールドが明確化のためにリネームまたは削除 (以下の breaking changes を参照)。

### 互換バージョン

- `cardano-node`: `11.0.1` (プロトコルバージョン 12+)
- `cardano-cli`: `11.0.0`
- `mithril`: `2617`

## Breaking Changes サマリー

### StateChanged イベントスキーマ (2.1.0)

| イベント | 変更内容 |
|---------|---------|
| `SnapshotRequested` | `snapshot` → `requestedSnapshot`; `requestedTxIds` 削除 (スナップショット内に包含) |
| `PartySignedSnapshot` | `snapshot :: Snapshot tx` → `snapshotNumber :: SnapshotNumber` |
| `SnapshotConfirmed` | `snapshot :: Snapshot tx` → `snapshot :: Maybe (Snapshot tx)` (`SnapshotRequested` が既にスナップショットを持つ場合は `Nothing`) |
| `DecommitRecorded` | `utxoToDecommit :: UTxOType tx` フィールド削除 |

### Hydra スクリプト

すべてのオンチェーンスクリプトが `preview`、`preprod`、`mainnet` ネットワーク全体で新しいハッシュを持ちます。最新のスクリプト参照については [networks.json](https://raw.githubusercontent.com/cardano-scaling/hydra/2.1.0/hydra-node/networks.json) を参照してください。

### 永続化の移行

V1 から V2 へのアップグレード時:
1. アップグレード前にすべてのオープンな Head を閉じる。
2. 2.1.0 の初回起動時に `state` ファイルが自動的に `hydra.db` に移行。
3. 元の `state` ファイルはバックアップとして `state.migrated` にリネーム。

## V1 から V2 への移行ガイド

1. **アクティブな Head をすべて閉じる** ノードアップグレード前に。
2. **スクリプト参照を更新**: すべての hydra スクリプトハッシュが変更 — `--hydra-script-catalogue` を更新するか `--network` フラグを使用。
3. **API コンシューマーを更新**: 新しい `StateChanged` イベントスキーマ (リネーム/削除されたフィールド) に合わせてクライアントコードを調整。
4. **Deposit ワークフローに適応**: commit-then-open パターンを direct-open-then-deposit に置き換え。
5. **永続化ディレクトリを確認**: 初回起動時に既存の `state` ファイルが自動的に SQLite に移行。
6. **関連ツールのアップグレード**: `cardano-node` `>= 11.0.1`、`cardano-cli` `>= 11.0.0`、`mithril` `>= 2617`。
