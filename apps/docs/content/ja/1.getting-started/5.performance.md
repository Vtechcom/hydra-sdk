# パフォーマンスと比較

## なぜ Hydra SDK は WASM を採用しているのか

Hydra SDK は、`@cardano-sdk` のような従来の **JavaScript ベース SDK** が抱える制約を解消するために、コア実装として **WebAssembly (WASM)** を採用しています。

ここでは、なぜ WASM ベースのアーキテクチャが最適なのか、その理由を整理します。

### WASM 採用の主な利点

1. **Node.js コアモジュール依存の排除**
   - 暗号処理、CBOR パース、トランザクション構築などの重要な処理を、`crypto` や `stream`、`fs` といった Node.js コアモジュールに依存せず、WASM サンドボックス内で完結させます。
   - これにより、**ブラウザ** と **Node.js** の両方で同じコードベースを安全に実行できます。

2. **バンドルサイズの削減**
   - `crypto-browserify` や `stream-browserify` といった polyfill を大量に読み込む必要がなくなります。
   - 必要な機能だけを WASM と最小限の JS glue コードとして読み込むことで、**バンドルサイズを大幅に削減** できます。

3. **高い実行性能**
   - 暗号処理やトランザクションパースなど CPU 負荷の高い処理は、WASM によって **ネイティブに近い速度** で実行されます。
   - JavaScript のランタイムオーバーヘッドを最小化し、ブラウザ環境でも安定したパフォーマンスを発揮します。

4. **クロスプラットフォーム互換性**
   - 単一の WASM バイナリを、ブラウザ・Node.js (WASI)・モバイル（Bridge 経由）など複数の環境で再利用できます。
   - CommonJS / ESM の相互運用や、環境ごとのビルド差分を意識せずに利用できます。

## Cardano SDK ソリューションの比較

### 詳細比較テーブル

| 観点                             | **`@cardano-sdk` ベースの SDK**                    | **Hydra SDK (WASM ベース)**              |
|----------------------------------|----------------------------------------------------|-----------------------------------------|
| **ブラウザ互換性**              | Node.js コアモジュールの polyfill が必須。`fs` や `net` はブラウザでは使用不可。 | ネイティブにブラウザ対応。polyfill 不要。 |
| **バンドルサイズ**              | polyfill により数百 KB〜1MB 超になることも多い。  | WASM + 最小限の JS のみでコンパクト。   |
| **Node.js 依存度**              | 高い。Node.js コアモジュールを直接 import。        | 依存なし。コアロジックはすべて WASM 内。 |
| **ESM / CJS 互換性**            | `exports is not defined` や `.default is not a function` などのエラーが発生しがち。 | 純粋な ESM JavaScript で問題なし。      |
| **Crypto / CBOR パフォーマンス**| Polyfill ベースの JS 実装で中程度。               | WASM により高性能・低オーバーヘッド。   |
| **クロスプラットフォーム対応**  | Node.js には強いが、ブラウザ対応は制約が多い。     | ブラウザ / Node.js / モバイルで高い互換性。 |
| **Tree-Shaking**                | Node.js imports が散在し、未使用コードも残りがち。 | 必要な WASM 関数だけをバンドル可能。    |
| **保守性・スケーラビリティ**    | Node.js API と polyfill の両方に追随する必要あり。 | Rust/C++ 実装 + WASM エクスポートのみ管理すればよい。 |

## 結論

Hydra SDK の WASM ベースアーキテクチャは、Cardano DApp に求められる **パフォーマンス**、**互換性**、**保守性** を高いレベルで両立します。

- Node.js 依存を排除し、ブラウザ / Node.js を問わず同じコードで動作
- polyfill をほぼ不要にし、モダンフロントエンド環境でのセットアップを大幅に簡素化
- 暗号処理やトランザクション処理を WASM で高速実行

従来の JavaScript ベース SDK で **バンドルエラー** や **polyfill 地獄** に悩まされている場合は、Hydra SDK への移行によって、開発体験と本番稼働時の安定性の両方を大きく改善できます。
