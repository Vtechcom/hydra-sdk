# Thay Đổi Trong Hydra V2

Hydra V2 đánh dấu bước tiến quan trọng của Hydra Head protocol. Từ phiên bản 2.0.0, giao thức đã được đơn giản hóa căn bản, giúp vận hành head dễ dàng hơn, giảm chi phí on-chain và giải quyết các vấn đề tồn đọng lâu năm.

## Tổng Quan

| Phiên bản | Ngày phát hành | Chủ đề chính |
|-----------|---------------|-------------|
| **2.0.0** | 2026-04-02 | Đơn giản hóa giao thức — loại bỏ giai đoạn commit, mở head trực tiếp |
| **2.1.0** | 2026-05-13 | Hiệu suất & bảo mật — event store SQLite, tối ưu snapshot, bảo vệ deposit |

## 2.0.0 — Đơn Giản Hóa Giao Thức

### Loại Bỏ Giai Đoạn Commit — Mở Head Trực Tiếp

Thay đổi căn bản nhất trong Hydra V2: **giai đoạn commit bị loại bỏ**. Trong V1, việc mở head yêu cầu tất cả participant commit UTxO trong giai đoạn khởi tạo (`Init` → `Commit` → `CollectCom`). Trong V2:

- Head mở **trực tiếp** sau khi khởi tạo — không còn transaction `commit`, `collectCom`, hay `abort`.
- Funds được thêm vào **từng bước** qua transaction `deposit` khi head đã mở.
- Quyết định này được ghi lại trong [ADR-33](https://hydra.family/head-protocol/adr/33).

**Lợi ích:**

- **Vòng đời đơn giản hóa**: Loại bỏ quy trình mở head nhiều bước, giảm độ phức tạp vận hành.
- **Giải quyết vấn đề "non-abortable head"**: Trước đây, một participant commit UTxO quá lớn có thể khiến head không thể abort. Vấn đề này không còn tồn tại.
- **Chi phí thấp hơn**: Loại bỏ transaction `collectCom` và `abort` giúp giảm tổng chi phí on-chain cho hầu hết use case. Xem [transaction cost benchmarks](https://hydra.family/head-protocol/unstable/benchmarks/transaction-cost).

**Thay đổi API:**

- Endpoint `/commit` thay đổi hành vi — giờ đây nhận trực tiếp transaction `deposit` vì head mở không cần giai đoạn commit trước.
- Endpoint khởi tạo head (`GET /head-initialization`) bị loại bỏ.
- Tất cả on-chain scripts thay đổi — script hashes mới trên tất cả các mạng.

### Token HydraHeadV2

Tên token head được nâng cấp từ `HydraHeadV1` lên `HydraHeadV2`. Điều này đảm bảo phân biệt phiên bản và ngăn tương tác giữa head V1 và V2.

### Conservative ADA Deposits

Cho đến khi [partial fanout](https://github.com/cardano-scaling/hydra/pull/2324) hoàn thành, giao thức khuyến khích giới hạn số ADA deposit để đảm bảo an toàn. Giới hạn cứng 100 ADA trên mainnet đã được gỡ bỏ để khớp với hành vi từ v1.3.0, nhưng cần thận trọng để đảm bảo an toàn toàn bộ funds.

### Sửa Lỗi

| Vấn đề | Mô tả |
|--------|-------|
| **Plutus Script Evaluation** | L2 ledger `Globals` giờ sử dụng `EpochInfo` theo era từ blockchain thay vì `fixedEpochInfo`, đảm bảo giá trị `POSIXTime` chính xác cho Plutus scripts nhạy cảm thời gian trên multi-era chains (mainnet/testnet). |
| **Kẹt ở RequestedSnapshot** | Sửa lỗi head bị kẹt vĩnh viễn khi `CommitFinalized` chạy song song với `ReqSn`. Chỉ `SeenSnapshot` chặn re-request; `RequestedSnapshot` retry chính xác. |
| **Deposit bị bỏ qua** | Deposit được kích hoạt trong khi snapshot đang xử lý không còn bị bỏ qua — snapshot tiếp theo sẽ pick up qua `selectNextDeposit`. |
| **Cross-Head Deposit Contamination** | Deposit từ head khác không còn bị pick up nhầm khi nhiều head dùng chung mạng — `depositsForHead` được áp dụng nhất quán. Deposit aggregate được guard bởi `headId`. |

- `cardano-cli`: `10.15.0.0`

## 2.1.0 — Hiệu Suất & Bảo Mật

### Event Store SQLite

File-based persistence (file JSON append-only `state`) được thay bằng **event store SQLite** (`hydra.db`):

- Events được lưu trong `<persistence-dir>/hydra.db`
- Khi khởi động lần đầu sau nâng cấp, file `state` cũ được **tự động migrate** vào `hydra.db` và đổi tên thành `state.migrated`
- Cải thiện hiệu suất khởi động và phục hồi của node

### Bảo Vệ Deposit

Deposit Plutus validator đã được tăng cường chống lại **malformed increment transactions**, đóng một lỗ hổng bảo mật trong xử lý deposit on-chain.

### Cải Thiện Độ Trễ Snapshot

Độ trễ xác nhận snapshot giảm **~7% (trung bình)** nhờ cache pre-computed signable bytes trong `SeenSnapshot`. Điều này tránh việc serialize và hash UTxO lặp lại trên mỗi lần xác minh `AckSn`.

### Khả Năng Chịu Lỗi Blockfrost

Lỗi chain-following tạm thời trong Blockfrost backend (`DecodeError`, `MissingNextBlockHash`, ...) giờ được retry với **exponential backoff** thay vì crash node. Lỗi HTTP-level API vẫn do upstream client library xử lý.

### Tối Ưu Cấu Trúc Dữ Liệu

- `List` được thay bằng `Seq` để tăng tốc xử lý transaction trong một số thao tác.
- Một số field trong `StateChanged` event được đổi tên hoặc loại bỏ (xem breaking changes bên dưới).

### Phiên bản tương thích

- `cardano-node`: `11.0.1` (protocol version 12+)
- `cardano-cli`: `11.0.0`
- `mithril`: `2617`

## Tổng Hợp Breaking Changes

### Schema StateChanged Event (2.1.0)

| Event | Thay đổi |
|-------|----------|
| `SnapshotRequested` | `snapshot` → `requestedSnapshot`; `requestedTxIds` bị loại bỏ (giờ nằm trong snapshot) |
| `PartySignedSnapshot` | `snapshot :: Snapshot tx` → `snapshotNumber :: SnapshotNumber` |
| `SnapshotConfirmed` | `snapshot :: Snapshot tx` → `snapshot :: Maybe (Snapshot tx)` (`Nothing` khi snapshot đã có trong `SnapshotRequested`) |
| `DecommitRecorded` | Field `utxoToDecommit :: UTxOType tx` bị loại bỏ |

### Hydra Scripts

Tất cả on-chain scripts có hashes mới trên các mạng `preview`, `preprod`, và `mainnet`. Tham khảo [networks.json](https://raw.githubusercontent.com/cardano-scaling/hydra/2.1.0/hydra-node/networks.json) để có script references mới nhất.

### Persistence Migration

Khi nâng cấp từ V1 lên V2:
1. Đóng tất cả head đang mở trước khi nâng cấp.
2. File `state` được tự động migrate sang `hydra.db` khi khởi động 2.1.0 lần đầu.
3. File `state` gốc được đổi tên thành `state.migrated` làm backup.

## Hướng Dẫn Migration từ V1 sang V2

1. **Đóng tất cả head đang hoạt động** trước khi nâng cấp node.
2. **Cập nhật script references**: Tất cả hydra script hashes đã thay đổi — cập nhật `--hydra-script-catalogue` hoặc dùng flag `--network`.
3. **Cập nhật API consumers**: Điều chỉnh code client cho schema `StateChanged` event mới (các field đổi tên/bị loại bỏ).
4. **Thích nghi deposit workflow**: Thay pattern commit-rồi-mở bằng mở-trực-tiếp-rồi-deposit.
5. **Kiểm tra persistence directory**: Khi khởi động lần đầu, file `state` cũ sẽ được tự động migrate sang SQLite.
6. **Nâng cấp công cụ đi kèm**: `cardano-node` `>= 11.0.1`, `cardano-cli` `>= 11.0.0`, `mithril` `>= 2617`.
