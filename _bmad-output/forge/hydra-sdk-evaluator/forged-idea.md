# @hydra-sdk/evaluator

- Offline transaction-level Plutus evaluator implementing `IEvaluator` for `@hydra-sdk/transaction`, so `TxBuilder.complete()` can obtain real exUnits without a provider, API key, or network I/O.
- This is not a thin wrapper around `@harmoniclabs/uplc`: the package must decode the transaction, resolve scripts/datums/UTxOs, build the era-correct ScriptContext, execute redeemers with cost accounting, and map results back to `EvalAction`.
- Offline is a strict contract: all UTxOs, datum/reference scripts, protocol parameters, cost models, era, and slot/time context come from the transaction, `additionalUtxos`/`additionalTxs`, or an explicitly supplied local context source. Missing context is a typed error; never fetch silently or return placeholder/zero budgets.
- Public surface should stay small: `createEvaluator`, `OfflineEvaluator`, `EvaluatorContext` / `EvaluatorContextSource`, `EvaluatorError`, and `evaluateTxDetailed`. `evaluateTx` remains the Mesh-compatible `IEvaluator` method; detailed mode adds diagnostics, pointer, script hash/language, budget, logs, context fingerprint, and failure phase.
- V1 supports Plutus V1/V2/V3 and `SPEND` + `MINT` end-to-end, matching the redeemer categories currently remapped by `TxBuilder`. `CERT`, `REWARD`, `VOTE`, and `PROPOSE` wait until evaluator and builder remapping have complete conformance coverage.
- Determinism is conditional on pinned context, cost-model hash, era/slot mapping, and engine version. Product claim: deterministic offline evaluation with pinned context, not default `cardano-node` equivalence.
- Every release needs differential conformance against a declared cardano-node/Ogmios oracle and a compatibility matrix covering Plutus language, protocol era, cost model, engine version, and permitted budget delta.
- Runtime targets are Node and browser/worker. No filesystem, process, network, provider fallback, submission, fee balancing, script compilation, step debugger, Hydra-ledger validation, or production-acceptance claim in V1.
- Use `@hydra-sdk/cardano-wasm` for Cardano CBOR objects; do not import `@emurgo/cardano-serialization-lib` directly. Keep the execution engine behind an adapter so it can be replaced without changing `IEvaluator`.
- Delivery gate: first prove one real Plutus V3 `SPEND` and one `MINT` fixture; then context resolver, transaction/redeemer mapping, V1-V3 engine adapter, diagnostics, and differential matrix. Stop or change engine before stabilizing the API if semantics or cost accounting do not match the oracle.
- Feasibility spike passed with MeshJS fixtures: `whisky-evaluator@0.1.1` (Rust/WASM) and `scalus@0.17.0` (Scala.js) matched `MINT[0] = { mem: 508703, steps: 164980381 }` and a V3 `SPEND[0] = { mem: 2001, steps: 380149 }`.
- Engine decision for the next spike: wrap Whisky behind a Hydra adapter; use Scalus as a second conformance oracle. Whisky provenance, embedded binary size, CSL beta version, browser packaging, and era coverage remain release gates.
